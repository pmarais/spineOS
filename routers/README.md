# routers/ — your task-specific processes

One markdown file per task type. When a task of that type arrives, the agent reads the router BEFORE acting (SPINE.md Prime Rule: use the registered process, never invent one).

Suggested starters as your spine grows: `onboarding.md` (lead → accepted promise), `delivery.md` (what leaves the building, and through which gate), `settlement.md` (how payments are confirmed — feeds are facts, messages are claims), `handover.md`.

A router wins on mechanics; SPINE.md wins on sequence and gates. See `examples/demo_spine/routers/delivery.md` for a worked example.
